Version 2.0 Last Updated: August 5, 2026 Status: Milestone 2 — Requirements Analysis

Project Summary

CuriousBooks is an AI-enhanced online bookstore that enables customers to browse, search, and purchase books, and receive personalized recommendations using content-based and collaborative filtering. The system supports authentication, catalog discovery, shopping cart, Stripe checkout, order history, profile management, and manager inventory CRUD, aligned with proposal wireframes UI 1–UI 13 and the site map.

Corresponding Functional Requirements (Implementation)

FR ID Implements Implementation Description
FR-AUTH-001 NFR-AUTH-001 The LoginPage (UI 7) provides a registration form. Form submission calls authApi.register() which sends a POST request to the Flask backend at /api/auth/register. The backend creates a new user record in the MySQL database and returns JWT tokens.
FR-AUTH-002 NFR-AUTH-002 Password validation is enforced on both frontend (HTML5 validation) and backend. The Flask auth.py route validates password requirements before hashing with bcrypt and storing in the users table.
FR-AUTH-003 NFR-AUTH-003 The LoginPage (UI 6) calls authApi.login(email, password) which sends a POST to /api/auth/login. The Flask backend validates credentials against the MySQL database and returns JWT access/refresh tokens stored in localStorage.
FR-AUTH-004 NFR-AUTH-004 Logout calls authApi.logout() which clears JWT tokens from localStorage via the clearTokens() function. Per the site map, the user remains on the current page unless the page requires login (profile, my orders, manage books), in which case the app redirects to the home page.
FR-AUTH-005 NFR-AUTH-005 Login routes accept a ?redirect= query (via loginRedirect.ts). After successful authentication, React Router navigates back to the prompting page (e.g. checkout or profile) instead of always sending the user to home.
FR-AUTH-006 NFR-AUTH-006 App.tsx route guards for /profile, /orders, /orders/:id, and /manage/books redirect unauthenticated users to /login. Manager/admin role is checked before rendering ManagerBooksPage; unauthorized users are redirected to login or home.

System Quality Attributes

Quality attributes and system constraints that define how the system should perform.

QA-PERF-001
Page Load Performance
The system shall load all pages within acceptable time limits to ensure a smooth user experience.
Target: Pages must load within 3 seconds on standard broadband connection
QA-PERF-002
Search Response Time
Search queries shall return results quickly to maintain user engagement and satisfaction.
Target: Search results displayed within 2 seconds
QA-PERF-003
Recommendation Response Time
Similar-book and personalized recommendation endpoints shall return results quickly enough to keep discovery fluid on search and synopsis pages.
Target: Recommendation API responses within 2 seconds for the prototype catalog size
QA-SEC-001
Password Security
User passwords must be securely stored using industry-standard encryption methods.
Standard: Passwords hashed using bcrypt with minimum 10 salt rounds
QA-SEC-002
Session Management
User sessions shall timeout after period of inactivity to protect user accounts.
Target: Sessions expire after 30 minutes of inactivity
QA-USE-001
Responsive Design
The application shall be fully functional and visually appealing across all device sizes.
Support: Desktop, tablet, and mobile viewports (320px - 2560px)
QA-USE-002
Accessibility
The application shall meet accessibility standards to ensure usability for all users.
Standard: WCAG 2.1 Level AA compliance
QA-REL-001
System Availability
The system shall maintain high availability to ensure customers can access the store.
Target: 99.5% uptime during business hours
QA-SCL-001
Concurrent Users
The system shall support multiple simultaneous users without performance degradation.
Target: Support 100 concurrent users minimum
